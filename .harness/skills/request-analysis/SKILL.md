# Request Analysis

## 定位

在动手编码前拆解需求、识别影响范围、判断复杂度并决定是否需要执行计划。本技能只分析和阅读，不直接修改代码。

## 触发条件

- 新功能、Bug、重构、接口调整、SQL 或配置调整。
- 任务涉及多个模块、前后端协作或跨服务。
- 涉及登录、OAuth2、租户、组织、数据权限、字段权限或开放 API。
- 需求不清晰、影响范围不确定或风险较高。

## 输入上下文

- 用户需求或问题描述。
- `AGENTS.md` 和 `ARCHITECTURE.md`。
- 根 `pom.xml` 和 `app-server/pom.xml`。
- 相关 Controller、Service、Mapper、DO、VO、枚举、SQL、测试。
- `.harness/wiki/` 中的业务域、API 契约、前端对接、数据模型文档。
- `.harness/rules/requirement-alignment-rule.md`。

## 执行步骤

1. 复述目标，确认要解决的实际问题。
2. 判断任务类型：功能、Bug、接口、SQL、配置、文档、跨模块或前后端联调。
3. 检查启用模块、服务装配和相关调用链。
4. 识别影响范围：后端模块、框架、服务装配、SQL、配置、接口协议、前端页面、权限和安全。
5. 按 L1-L4 分级：
   - L1：小 Bug、单字段、纯文档，可直接实现。
   - L2：新增接口、字段调整、局部 SQL，需要影响分析。
   - L3：多接口、多状态、多表、多角色，需要方案和计划。
   - L4：登录、OAuth2、Token、租户、组织、权限、跨模块或破坏性 SQL，必须先方案再编码。
6. 判断是否触发 Owner 审批或 `frontend-backend-integration`。
7. 判断是否需要在 `.harness/changes/active/` 建立执行计划。
8. 输出分析结果。

## 输出格式

```text
目标：
任务类型：
影响范围：
后端模块：
SQL/配置：
接口协议：
前端影响：
复杂度级别：
是否触发审批：
是否需要执行计划：
是否需要前后端联调：
风险点：
建议下一步：
```

## 停止条件

- 需求目标不明确。
- 文档与代码事实冲突。
- 影响范围无法判断。
- 任务属于必须人工确认范围。

## 验证要求

本技能只读不改，不执行编码或验证命令。
