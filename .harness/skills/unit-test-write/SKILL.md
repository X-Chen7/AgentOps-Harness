# Unit Test Write

## 定位

为后端变更补充有价值的最小测试，不为了覆盖率写无意义测试。

## 触发条件

- 新增业务规则或状态流转。
- 修复 Bug。
- 修改登录、OAuth2、权限、组织、SQL。
- Review 发现测试缺口。

## 输入上下文

- 被测代码。
- 现有测试风格和测试基类。
- 业务规则、枚举、错误码。
- 接口契约示例。

## 测试设计步骤

1. 找到现有测试风格和基类。
2. 确认被测行为。
3. 覆盖成功路径。
4. 覆盖失败路径和错误码。
5. 覆盖边界条件：空值、超长、过期、越权、重复。
6. 避免依赖外部不可控资源，必要时 Mock。
7. 测试数据尽量与接口契约示例一致。
8. 运行受影响模块测试。

## 输出格式

```text
新增测试：
覆盖场景：
未覆盖原因：
验证命令：
结果：
```

## 停止条件

- 测试需要真实生产数据。
- 依赖外部系统且无 Mock。
- 当前测试基建缺失且无法局部补齐。

## 验证要求

新增测试后必须执行受影响模块测试；无法执行时说明原因。
