# Unit Test CI

## 定位

按影响范围选择最小验证命令，执行测试或打包，并准确说明失败原因。

## 触发条件

- 代码修改后。
- SQL 或配置修改后。
- Review 前。
- 交付前。

## 输入上下文

- 修改文件。
- 影响模块。
- 根 `pom.xml` 和 `app-server/pom.xml`。
- 变更范围对应的验证命令。

## 命令选择

| 影响范围 | 命令 |
| --- | --- |
| system 模块 | `mvn -pl app-module-user -am test` |
| infra 模块 | `mvn -pl app-module-infra -am test` |
| app-core 模块 | `mvn -pl app-module-app-core -am test` |
| 服务启动/装配/配置 | `mvn -pl app-server -am package -DskipTests` |
| 接口契约冒烟 | 使用 curl 或 Postman 验证关键接口 |

## 执行步骤

1. 判断影响模块。
2. 选择最小命令。
3. 执行验证并记录结果。
4. 失败时分析首个根因。
5. 判断失败是否与本次修改相关。
6. 输出验证结论。

## 失败归因

- 本次修改引发：修复后重跑。
- 历史失败：记录并说明。
- 环境依赖失败：说明缺失内容。
- 网络或依赖下载失败：说明未验证范围。

## 输出格式

```text
执行命令：
结果：
失败原因：
是否与本次修改相关：
未验证范围：
```

## 停止条件

- 已执行完成最小验证。
- 或验证被环境、网络、数据库阻塞且已说明原因。
- 或发现明确根因需要回到编码技能修复。
