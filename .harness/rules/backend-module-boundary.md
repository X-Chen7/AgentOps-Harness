# .harness/rules/backend-module-boundary.md

## 1. 文件定位

本文件定义示例后端后端模块边界。

## 2. 总体原则

- 业务逻辑落在对应 `app-module-*`；
- 公共能力落在 `app-framework`；
- 启动和装配落在 `app-server`；
- SQL 统一放在 `sql/`；
- 未启用模块默认不修改。

## 3. 模块职责

| 模块 | 职责 |
| --- | --- |
| `app-module-user` | 用户、租户、权限、登录、OAuth2 |
| `app-module-infra` | 配置、文件、代码生成、监控、任务 |
| `app-framework` | Starter、公共工具、横切能力 |
| `app-server` | 启动、装配、配置、打包 |
| `sql/` | 表结构、初始化数据、迁移脚本 |

## 4. 修改边界

- 业务需求优先在对应业务模块解决；
- 只有多个模块复用或框架缺陷时才修改 `app-framework`；
- 只有启动、配置、装配、打包问题才修改 `app-server`；
- 数据库变更必须同步 SQL。

## 5. 跨模块调用

- 跨模块稳定接口放在 `api` 模块；
- 不跨模块直接访问其他模块 Mapper；
- 不复制其他模块业务逻辑；
- 必要时通过 Service API 或事件解耦。

## 6. 禁止事项

- 不在 `app-server` 堆业务逻辑；
- 不在 `app-framework` 写项目专属业务；
- 不把基础设施能力塞进业务模块；
- 不修改未启用模块完成当前需求。

## 7. 检查清单

修改前确认：

- 目标模块是否启用；
- 是否属于该模块职责；
- 是否需要跨模块接口；
- 是否影响启动装配；
- 是否涉及 SQL。
