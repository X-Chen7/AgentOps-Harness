# .harness/rules/sql-and-migration.md

## 1. 文件定位

本文件定义数据库脚本和迁移规则。

## 2. SQL 目录规则

- 数据库脚本统一放在 `sql/`；
- 当前项目专项脚本可放在 `sql/mysql/<project>/`；
- 初始化、结构变更、数据修复应分文件管理；
- 文件名应体现用途、版本或日期。

## 3. 变更分类

| 类型 | 示例 | 要求 |
| --- | --- | --- |
| 结构变更 | 建表、加字段、索引 | 同步 DO、Mapper、测试 |
| 初始化数据 | 菜单、角色、客户端 | 标明用途和环境 |
| 修复脚本 | 修正历史脏数据 | 必须人工确认 |
| 回滚脚本 | 撤销变更 | 高风险变更必须提供 |

## 4. 同步要求

涉及字段变化时同步检查：

- DO 字段；
- Mapper 查询；
- XML SQL；
- VO / DTO；
- 初始化 SQL；
- 建表 SQL 字段中文注释；
- 单元测试或最小验证。

## 4.1 字段注释要求

- 新增表的每个业务字段、审计字段、租户字段、逻辑删除字段都必须提供中文字段注释。
- MySQL 正式脚本必须使用 `COMMENT '中文说明'` 描述字段含义。
- H2 / 单元测试建表脚本如果支持 `COMMENT`，应与正式脚本保持字段中文说明一致。
- DO 字段注释、SQL 字段注释、`.harness/wiki/data-model.md` 中的重要字段语义必须保持一致。
- 字段含义无法明确时，不得先提交无注释字段，应先补充业务语义。

## 4.2 枚举和状态字段注释要求

- 凡是 `type`、`status`、`*_type`、`*_status`、`flag`、`result`、`scope`、`effect`、`action` 等具备固定取值集合的字段，SQL 字段注释必须写明取值映射。
- 取值映射统一使用 `字段含义：key1=value1，key2=value2` 格式，例如 `状态：0=开启，1=关闭`。
- 布尔或 bit 字段也必须写明映射，例如 `是否组织管理员：0=否，1=是`。
- 如果字段值来源于系统字典，注释中至少写明核心取值，并在数据模型或字典初始化中标明对应字典类型。
- 如果字段值来源于 Java 枚举，SQL 注释、Java 枚举、DO / VO 注释和初始化数据必须保持一致。
- 如果枚举值尚未最终确定，不得只写“状态”“类型”等泛化描述；必须先在设计文档中明确当前阶段允许值和预留值。
- 新增或调整枚举值时，必须同步检查建表 SQL、迁移 SQL、初始化数据、Java 枚举、DO / VO 注释、接口文档和前端对接说明。

## 5. 兼容性要求

- 避免只适用于单一数据库的语法；
- MySQL 与 KingbaseES 差异必须注明；
- 字段类型、默认值、索引长度需审查；
- 时间、布尔、JSON 等类型需谨慎处理。

## 6. 回滚要求

高风险变更必须提供：

- 回滚脚本；
- 数据备份说明；
- 影响范围；
- 验证方式。

## 7. 审批边界

删除表、删除字段、批量更新、批量删除、历史数据修复必须人工确认。

## 8. 禁止事项

- 不把结构变更和高风险数据修复混在一个脚本；
- 不提交无法解释用途的初始化数据；
- 不提交缺少中文字段注释的新增表或新增字段；
- 不直接写生产账号、密钥、真实敏感数据；
- 不在未确认业务含义时删除字段。

## 9. app-core 敏感字段分级补充规则

- 敏感字段分级统一使用 `sensitivity_level` 字段。
- `sensitivity_level` 的取值映射必须固定为：1=一般，2=内部，3=敏感，4=高敏感。
- 字段权限策略表、字段访问审计表、DO、VO、Java 枚举、初始化数据和前端对接说明必须保持该映射一致。
- 字段访问审计只允许记录字段编码、敏感级别、处理动作、访问上下文和处理结果，不得记录字段原始敏感值。
- 新增敏感字段策略时，SQL 注释必须写明完整 key-value 映射，不能只写“敏感级别”“字段级别”等泛化描述。
