# 基准测试骨架

本目录定义 Codex-only 的 Harness 基准任务，用于对比使用与不使用 Harness 规则、技能和状态时，同一任务的执行效果。

## 基准任务

| ID | 任务 | 输入描述 | 预期产出 | 验证方式 |
| --- | --- | --- | --- | --- |
| B-01 | 改接口 | 现有只读接口新增分页、筛选和排序参数，不破坏旧调用 | Controller、Service、VO 和测试同步更新，接口文档说明新参数 | 模块测试通过，旧参数请求不回归，API 契约文档已更新 |
| B-02 | 加表 | 提供新业务表的字段清单和 CRUD 需求 | SQL 迁移、DO、Mapper、Service、Controller、测试和数据模型文档 | 新库可执行迁移，模块测试通过，SQL 与代码同步检查通过 |
| B-03 | 联调 | 给定新接口定义和前端页面原型 | 前后端按契约联调可用，错误码和权限处理完整 | 本地端到端请求通过，联调文档和示例请求已记录 |
| B-04 | Review | 给定一个变更 diff 和需求说明 | 按严重度排序的问题清单，标注文件行号和测试缺口 | 每个问题可定位到文件和行号，阻塞问题已修复 |
| B-05 | Git 同步 | 给定一个已完成功能分支和提交记录 | feature-list 状态、commit hash、PROGRESS、completed 记录同步更新 | `script\check.ps1` 通过，Git 记录与状态文件一致 |
| B-06 | 文档同步 | 给定接口或数据模型变更 | api-contract、data-model、feature-design 等知识文档同步更新 | 文档链接有效，新增字段和接口均有说明，无过期内容 |
| B-07 | 复杂权限变更 | 为组织增加数据权限或临时授权规则 | 权限模型、枚举、Service、测试和设计文档完整更新 | 权限边界测试通过，Review 确认未绕过数据权限 |

## 对比指标

| 指标 | 定义 |
| --- | --- |
| 是否用 harness | 执行时是否启用 `.harness` 入口、规则、技能和状态 |
| 耗时 | 从任务开始到验收通过的总分钟数 |
| 返工次数 | 验收发现问题后重新修改的次数 |
| 文档遗漏数 | 应更新但未更新的 wiki、契约、feature-list 文件数 |
| 验证失败数 | 测试、check 脚本或部署验证的失败次数 |

## 执行方法

每个任务在同一仓库状态下执行两次：一次仅给任务输入，一次启用 Harness 完整流程。每次执行后记录上述五类指标，结果写入基准测试结果文件，不修改 `.harness\changes\*` 和现有业务代码。
