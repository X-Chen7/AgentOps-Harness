# Frontend Backend Integration

## 定位

在前后端分离的协作模式下，以接口契约为唯一共同语言，驱动两端开发、联调和验收闭环。

## 核心原则

- 契约优先，代码后行。
- 后端未更新接口契约前，接口变更不算完成。
- 前端未按契约完成联调验收前，功能不算交付。
- 两端各自验证，再做联合验收。

## 触发条件

- 后端接口新增、修改或删除。
- 前端页面需要对接新接口。
- 请求、响应、枚举、错误码、分页、认证、租户或权限语义变化。
- 前后端联调失败或字段理解不一致。

## 输入上下文

- `AGENTS.md`、`ARCHITECTURE.md`。
- `.harness/wiki/api-contract.md`。
- `.harness/wiki/frontend-integration.md`。
- 相关 Controller、VO、枚举、错误码、SQL。
- 前端页面、原型或接口说明。

## 执行步骤

1. 确认变更范围和两端负责人。
2. 核对契约基线：
   - 路径、Method、Content-Type。
   - 请求参数、响应结构、分页参数。
   - 枚举、状态码、错误码。
   - 认证方式、租户头、权限要求。
   - 时间格式、空值、文件上传、跨域。
3. 后端先更新 `api-contract.md` 和 `frontend-integration.md`。
4. 生成联调包，包含接口说明、curl、请求响应样例、枚举表、错误码表、环境地址。
5. 前端按联调包开发，后端按契约完成接口自测。
6. 确认联调环境：baseUrl、token、租户、代理、CORS。
7. 执行联合验收并记录结果。
8. 未决问题进入技术债或下一轮联调。

## 联调包格式

```text
接口/页面：
变更方：
后端分支/提交：
前端分支/提交：
接口定义：
请求示例：
响应示例：
枚举：
错误码：
认证/租户：
联调环境：
后端验证：
前端验证：
未决问题：
```

## 联合验收清单

- 请求参数与契约一致。
- 响应结构、空值、类型与契约一致。
- 分页、排序、筛选正确。
- 枚举文案和值一致。
- 错误码和异常提示可读。
- Token、租户、权限头正确传递。
- 文件上传、下载、跨域可用。
- 前后端环境地址一致。

## 停止条件

- 接口契约未确认或字段含义不一致。
- 后端未更新契约文档。
- 联调环境不可用且无法说明。
- 涉及生产环境或真实用户数据。

## 验证要求

后端执行接口自测，前端执行页面验证，最后必须给出联合验收结论。
