# 修改边界

- 先确认目标模块和启用状态，再修改。
- 优先在所属业务模块内完成改动。
- 只有跨模块复用、框架缺陷、Starter 能力或横切能力需要时，才修改框架层。
- 涉及启动、配置、打包、模块装配时，优先检查服务入口模块。
- 涉及数据库字段、结构、初始化数据或修复数据时，代码、Mapper、DO、SQL 必须同步。
- 不做无关重构、大范围格式化、批量改名。
- 不主动修改与当前任务无关的文件、依赖版本或构建配置。
- 公共方法、DO/VO、复杂业务逻辑应补充必要中文注释。

# 禁止事项

- 不修改未确认启用的模块，除非用户明确要求。
- 不绕过认证、权限、租户和数据权限。
- 不删除用户已有改动。
- 不执行破坏性 Git 操作，如 `reset --hard`、强制覆盖。
- 不为了通过编译注释业务逻辑或绕过校验。
- 不把一次性计划写进 `AGENTS.md`。
- 不把详细业务设计、接口说明、表结构或排查记录写进 `AGENTS.md`。
